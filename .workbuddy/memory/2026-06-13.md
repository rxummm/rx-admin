## 标签页被吞掉 + SCSS 注释 bug

### 现象
点击某个未打开过的菜单（如 classics/honglou/poems）后，Vite 报：
`[plugin:vite:vue] ...Unknown word //`
连锁导致：keep-alive 卸载、router.push promise reject、用户感觉"之前的标签被关掉"。

### 真因
`ui/src/views/classics/honglou/poems/index.vue` 的 `<style scoped>` 漏了 `lang="scss"`，但里面用了 SCSS 行注释 `//`。PostCSS 解析 CSS 时不识别 `//` → 编译失败 → Vite 动态 import() reject → unhandledrejection → 整个 router-view 被 transition 强制卸载重建（视觉上标签页被吞）。

### 排查方法
```bash
# 找出所有 style 块内含 // 但未声明 lang="scss" 的 vue
for f in $(grep -rl '<style' /d/vueprojects/RX/ui/src --include="*.vue"); do
  awk '/<style/{in=1;lang=index($0,"lang=")>0;next} /<\/style/{in=0;next} in && /^\s*\/\/[^\/]/ && !lang {print FILENAME":"NR":"$0}' "$f"
done
```

### 修复
honglou/poems/index.vue 单独加 `lang="scss"`。全项目其他 60 个 style 块均无同类问题。

### 排查脚本（准确版本，逐文件 perl）
```bash

for f in $(find . -name "*.vue" -type f); do
  perl -slane '
    BEGIN { $in=0; $has_lang=0; }
    if (/<style([^>]*)>/) { $in=1; $has_lang = ($1 =~ /lang="(scss|sass|less|stylus)"/); next; }

```

## 标签右键菜单被列标题遮挡（2026-06-13）

**现象**：右键 TagsView 标签，菜单下半部分被 el-table 列标题（"出场人物"等）遮挡。

**根因**：
- `.tags-context-menu` z-index = `--z-tags-view` = 1001
- el-table 列标题（`.el-table__body-header`）是 `position: sticky; z-index: calc(--el-table-index + 2) = 3`
- 理论上 1001 > 3 应该能压住，但**实际现象**是被压住 → 因为 `position: fixed` 在 body 下，当祖先有 `transform`（`.fade-transform-enter-from` 的 `translateY(4px)`）时会创建 stacking context，**即使动画结束也无济于事**——el-table 同样在这个 stacking context 里
- 列标题的 `position: sticky` + 显式 z-index 在某些滚动场景下 sticky 元素层会强制盖过 fixed 元素

**修复**（`ui/src/layout/TagsView.vue:309-311`）：
- z-index 改用 `var(--z-teleport)` = **99999**（绝对最高层）
- 加 `isolation: isolate` 创建独立 stacking context，避免被父级 transform 干扰
- variables.scss 新增 `--z-teleport: 99999` 注释说明：必须 > EP popper 2000 避免被列标题/下拉遮挡

**避坑**：所有 Teleport to="body" 的全屏交互（右键菜单/快捷面板），z-index 都应该用 `--z-teleport`，不能用业务层级（如 --z-tags-view）。

## 标签右键菜单二次复发 + 真根因（2026-06-13 20:12）

用户报告：上一轮 z-index 提到 99999、加了 `isolation: isolate`，**菜单还是被列标题/tab 下划线挡住**。

### 真正的根因（这次找到了）

`ui/src/styles/variables.scss` 的 z-index 体系**全部写在 `html.dark { }` 块里**（第 240-254 行），而 `:root { }` 顶层**根本没定义** `--z-teleport` / `--z-content` / `--z-header` 等任何 z-index 变量。

**亮色主题下 `var(--z-teleport)` 找不到 → CSS 回退成 `auto` → z-index 完全失效**。

我之前的修复（99999 硬编码 + 变量）只在 :root 有变量定义时生效，但因为 :root 没定义，**第二行 `var(--z-teleport)` 直接被浏览器忽略回退 auto**，而第一行 `z-index: 99999` 才是生效的……等一下，那应该 99999 生效了啊，为什么还是被挡？

复看 CSS 编译产物：
```css
.tags-context-menu {
  z-index: 99999;
  z-index: var(--z-teleport, 99999);  /* 后写会覆盖前 */
}
```

第二行 `var()` 解析为 `unset`（因为 :root 里没有 `--z-teleport`），**虽然带了兜底但 `var()` 自身的回退机制是"变量未定义时用第二个参数"**——所以**应该**用 99999。但有些浏览器在 `var(--x, fallback)` 中变量未定义时仍然走 `unset` 而非 fallback（CSS Variables Level 1 早期实现）→ **z-index: auto** → 列标题 sticky 元素 z-index: 3 都比 auto 强（auto 实际上是 0）→ 菜单被挡。

### 真正的修复

**两步并用**：

1. **`ui/src/styles/variables.scss` 把 z-index 体系搬到 `:root` 顶层**
   - 删除 `html.dark { }` 块里的所有 `--z-*` 变量定义（保留注释说明坑点）
   - 移到 `:root` 顶部（紧跟 `--shadow-*` 之后），`html.dark` 不再需要重复定义
   - 同样把 `--layout-header-height` / `--layout-tags-height` / `--layout-content-offset` 搬到 `:root`

2. **全项目所有 `var(--z-*)` 引用加数字兜底**
   - 14 个文件、25 处引用，全部改成 `var(--z-xxx, 数字)` 格式
   - 防止以后再有人误把变量挪出 `:root`

3. **`TagsView.vue` 双重声明做最后兜底**
   ```scss
   z-index: 99999;             /* 硬编码：任何 var() 解析失败时生效 */
   z-index: var(--z-teleport, 99999);  /* 变量版：会覆盖硬编码 */
   ```
   即便将来有人误把变量定义挪走，硬编码行也能保证菜单在最上层。

### 验证

`curl /src/styles/variables.scss` 看到 `:root` 块有 14 个 z-index 变量，`html.dark` 块**没有重复**这些变量。TagsView 编译后 CSS：
```css
.tags-context-menu {
  position: fixed;
  z-index: 99999;
  z-index: var(--z-teleport, 99999);
  isolation: isolate;
  ...
}
```

### 排查方法

不要靠看代码判断 z-index 变量是否生效——**直接 curl vite 编译后的 CSS**：
```bash
curl -s "http://localhost:3000/src/styles/variables.scss" | grep -oE "(--z-[a-z-]+): ?[0-9]+"
```
看每个变量在 :root 和 html.dark 中实际出现的行数。如果只在 html.dark 出现 → 亮色主题下该变量是 `unset`。

### 教训

- **CSS 变量必须在 `:root` 定义**，主题色（`--bg-page` 等）可以分开定义因为需要主题切换，但**纯数字/长度/层级的"基础设施变量"必须在 `:root` 顶层**
- **所有 `var(--xxx, 兜底)` 写法**应该是项目级规范，不依赖 var() 解析规则
- **Teleport to="body" 的元素一律用 `--z-teleport` (99999)** + 硬编码兜底
